# 七项能力验收矩阵

这份矩阵用于把“解决大型项目中的 7 个 AI 编程痛点”转成可重复验收的产品能力。

原 `dev` 分支只正式标注了痛点 5、6、7：

- 痛点 5：长链条任务走丢、跨会话从零开始。
- 痛点 6：代码历史决策不可见。
- 痛点 7：项目隐式约定对 AI 不可见。

仓库中没有保存痛点 1-4 的正式名称。下表按当前 `main` 的真实能力给出工作定义；对外介绍前，
团队应确认名称和边界，并将确认后的定义保留在本文件。

## 验收原则

- 每项必须有固定输入、预期输出和实际证据。
- `ok=true` 不等于结果有用，必须检查内容质量。
- 自动化测试验证契约和降级行为；真实 Qoder 验收验证客户端、Windows 路径和超时。
- 不把实验开关能力计入稳定版完成度。
- 结论只使用：通过、部分通过、未通过。

## 当前矩阵

| 编号 | 工作定义 | 主要工具 | 当前判断 | 关键缺口 |
| --- | --- | --- | --- | --- |
| 1 | 大型仓库中快速定位相关代码 | `brain_context_for_task`, sidecar graph search | 部分通过 | 需要真实大型仓库准确率与耗时基准 |
| 2 | 理解符号调用关系和修改影响范围 | `brain_explain_symbol` | 部分通过 | 需要跨语言、动态调用和中文路径用例 |
| 3 | 控制上下文体积，只返回任务相关信息 | `brain_context_for_task` | 部分通过 | 尚未冻结 token/结果数量预算和质量指标 |
| 4 | 代码变化后保持索引新鲜且不阻塞客户端 | `brain_sync_status`, `brain_sync_project`, `brain_index_job_status` | 部分通过 | job 仅进程内保存，缺少断点恢复和长任务基准 |
| 5 | 跨会话延续关键任务上下文 | session memory 6 工具 | 通过 | 仍依赖 AI/用户主动记录，缺少质量治理 |
| 6 | 查看代码历史原因和关联变更 | Git 只读 3 工具 | 部分通过 | 安全的语义历史索引仍是实验能力 |
| 7 | 让 AI 在修改前遵守团队约定 | conventions 4 工具 | 通过 | 需要持续清理过期、冲突和低质量约定 |

“通过”表示稳定工具链已覆盖核心闭环，不表示所有项目均已验证。

## 固定验收用例

### 能力 1：相关代码定位

输入：

```text
任务：修改登录失败后的错误码映射
仓库：一个不少于 10 万行的真实业务仓库
```

步骤：

1. 调用 `brain_context_for_task`。
2. 记录耗时、返回符号和文件。
3. 由熟悉项目的开发者标注前 5 个结果是否相关。

通过条件：前 5 个结果中至少 3 个直接相关，且没有返回大段无关源码。

### 能力 2：调用关系和影响范围

步骤：

1. 选择一个有明确调用者和被调用者的业务函数。
2. 调用 `brain_explain_symbol`。
3. 与 IDE 引用搜索和人工代码审查结果对比。

通过条件：找到主要定义和直接调用关系；遗漏和误报被记录。

### 能力 3：上下文体积

步骤：

1. 对固定任务调用 `brain_context_for_task`。
2. 保存返回 JSON 的字符数、条目数和开发者相关性评分。

通过条件：结果是任务摘要和引用，不是全仓库内容倾倒。正式数值阈值待团队基准后冻结。

### 能力 4：索引新鲜度

步骤：

1. 完成一次 `brain_sync_project` 并轮询到成功。
2. 调用 `brain_sync_status`，应返回无需同步。
3. 修改一个纳入索引的源码文件。
4. 再调用 `brain_sync_status`，应返回需要同步。
5. 异步同步期间确认 Qoder 仍可继续对话。

通过条件：变化检测正确，异步 job 最终状态明确，失败时有错误信息。

### 能力 5：跨会话记忆

步骤：

1. `start_session`。
2. 记录一个决策、一个问题和一个文件变更。
3. `end_session`。
4. 新会话用相似任务调用 `recall_context`。

通过条件：能召回刚保存的关键事实，且不包含未记录的敏感数据。

### 能力 6：历史上下文

步骤：

1. 对一个历史丰富的文件调用 `get_recent_changes` 和 `get_blame`。
2. 调用异步 `get_co_changed_files` 并轮询结果。
3. 与 Git 命令人工核对。

通过条件：最近提交和 blame 正确；共同变更结果有解释价值；默认无需开启 Git 历史向量索引。

### 能力 7：团队约定

步骤：

1. 准备一条明确、可验证的模块约定。
2. 调用 `index_convention_files`。
3. 用相关任务调用 `search_conventions` 和 `brain_context_for_task`。
4. 用不相关任务检查误命中。

通过条件：相关任务能命中约定，不相关任务不会把该约定列为关键规则。

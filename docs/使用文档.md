# Codebase Brain — AI 编程大型项目增强方案

> 让 AI 编程工具（Qoder / Windsurf / Cursor / Codex / Claude Code / OpenCode）在大型项目中理解代码结构、项目约定、历史决策和跨会话上下文。

## 2. 拉取与部署

### Windows（推荐）

```powershell

git clone https://github.com/jjjojoj/codebase-brain.git C:\codebase-brain
cd C:\codebase-brain

# 创建虚拟环境并安装依赖（首次约 2-3 分钟）

.venv\Scripts\pip install mcp "pymilvus[milvus_lite]" sentence-transformers pyyaml openai httpx
```

下载 `codebase-memory-mcp-windows-amd64.zip`，解压后将 `codebase-memory-mcp.exe` 放到固定路径（如 `C:\codebase-memory\`）。

```bash

cd ~/codebase-brain
```

## 3. MCP 是什么

**MCP（Model Context Protocol）** = AI 模型的"函数调用协议"。

```
你（用户）→ 对话 → AI 编程工具 → MCP 协议(JSON-RPC) → MCP Server → 数据库/文件
```

AI 在对话中可以自动调用 MCP Server 提供的工具，像代码里调用函数一样。它比"把所有代码塞进上下文"高效得多——AI 只在需要时才查询相关信息。

## 4. 覆盖的 7 个痛点

| # | 痛点 | 解决工具 |
|---|------|---------|
| 1 | 上下文压缩返工 | `search_graph` 精确定位代码 |
| 2 | AI 动了不该动的代码 | `get_architecture` 模块边界 |
| 3 | 修改影响面不可知 | `trace_path` 调用链追踪 |
| 4 | 盲人摸象 | `get_architecture` 项目全景 |
| 5 | 长链条任务走丢 | `session-memory-mcp` — 会话记忆 + 跨会话召回 |
| 6 | 历史决策不可见 | `history-mcp` — git 历史索引 |
| 7 | 隐式约定缺失 | `conventions-mcp` — 约定文件索引 |

痛点 1-4 由 codebase-memory-mcp 覆盖，痛点 5-7 由本项目的 3 个 MCP Server 覆盖。

## 7. 为什么这么做

### 核心矛盾
大型项目几十万行代码，AI 上下文窗口只有几千行。grep 和逐文件读取在大项目上效率极低。

### 分层设计
```
Layer 3: 知识层 ← codebase-brain（约定 + 记忆 + 历史）
Layer 2: 结构层 ← codebase-memory-mcp（代码图谱 + 调用链）
Layer 1: 搜索层 ← 混合搜索 BM25 + 向量 RRF 融合
```

### 为什么 4 个独立 MCP
模块化部署、独立升级、按需启用。团队可以只用 conventions-mcp。

## 9. 如何调用

### 自动调用（配好 AGENTS.md 后）

| 场景 | AI 自动调用 |

## 10. 注意事项

1. **首次加载模型慢**：bge-m3 首次下载约 2GB，需 1-2 分钟。后续秒启动
2. **数据位置**：
   - Windows: `C:\Users\<用户名>\.codebrain\milvus.db`
   - Linux/macOS: `~/.codebrain/milvus.db`
3. **模型一致性**：索引和搜索必须用同一种 Embedding Provider
4. **约定文件格式**：必须带 YAML frontmatter（module + title）
5. **三个 MCP 互相独立**：可同时运行，可部分启用
6. **Python 版本**：需要 Python 3.12+
7. **git 历史只索引文本**：不索引二进制文件
8. **全本地运行**：不上传任何数据到云端

## 11. 异常处理

| 异常 | 原因 | 解决 |
|------|------|------|
| `ModuleNotFoundError: milvus_lite` | 缺少依赖 | `pip install pymilvus[milvus_lite]` |
| `Milvus client is not initialized` | DB 损坏或不存在 | 删除 `.codebrain/milvus.db`，重启 |
| `Failed to load embedding model` | 模型未下载 | 等自动下载，或手动运行一次 |
| `project not found` | 项目未索引 | 先执行 `index_repository` |
| MCP 工具不显示 | 进程启动失败 | 终端手动运行 command 验证 |
| `exec: "wsl": not found` | 工具已直接连 WSL 环境 | 去掉 `wsl`，直接用 Linux 路径 |
| 搜索结果少 | 索引未完成 | `index_status` 检查状态 |
| `ok: false, error: "..."` | 工具执行出错 | 看 error 字段详情 |

## 12. 常见问题

**Q: 三个 MCP 必须全部部署？**
A: 不需要。每个独立，可按需启用。建议从 conventions-mcp 开始。

**Q: 和 codebase-memory-mcp 冲突？**
A: 不冲突。codebase-memory 做代码结构（图），codebase-brain 做项目知识（向量），互补。

**Q: 数据安全吗？**
A: 完全本地。数据存在 `.codebrain/milvus.db`，不上传任何数据。

**Q: 支持中文？**
A: 完全支持。bge-m3 中文友好，约定模板也是中文。

**Q: 需要 GPU 吗？**
A: 不需要。CPU 运行 bge-m3 完全够用。

**Q: 怎么验证是否正常？**
A: AI 工具里说"用 health 检查"，应返回 `{"ok": true, "milvus": true}`。

**Q: 约定文件放哪？**
A: 项目根目录的 `.codebrain/conventions/`，Markdown 格式，YAML frontmatter。

**Q: Windows 和 Linux 路径差异？**
A: 本项目跨平台兼容。Windows 用 `\` 路径，Linux/macOS 用 `/` 路径。

**Q: 代码用什么框架？**
A: FastMCP（mcp 包），Python 3.12+。

**Q: 可以从任何 AI 编程工具调用吗？**
A: 是的。任何支持 MCP 协议的工具都可以（Qoder、Windsurf、Cursor、Claude Code、Codex、OpenCode 等）。

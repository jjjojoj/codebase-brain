# 代码风格约定

## 目标
保持代码可读、可维护，并减少团队成员在格式和命名上的分歧。

## 约定
- 函数和变量使用能表达业务含义的名称，避免模糊缩写。
- 公共接口必须包含类型标注，复杂返回值优先使用结构化类型。
- 单个函数只承担一个清晰职责；出现重复流程时提取本地辅助函数。
- 注释解释原因和边界条件，不重复代码本身已经表达的内容。

## 示例
使用 `calculate_invoice_total()` 表达业务动作，避免使用 `calc()` 这类含义不足的名称。
